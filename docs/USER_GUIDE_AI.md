# AI 功能使用指南（面向 admin / 评委 / 参赛者）

> 这是一份给"使用者"看的指南 — 不是给开发者。如果你想看 API 端点 / 架构设计，看 [AI_FEATURES_API.md](./AI_FEATURES_API.md)。

## 1. 我是谁，能用什么？

| 角色 | 能用的 AI 功能 | 在哪用 |
|---|---|---|
| **Admin**（管理员） | 全部 6 个：项目分析、评分一致性、内容审核、内容生成、抄袭检测、AI Metrics | `/admin/ai-features` |
| **评委** | 评分时看到 AI 建议（如果有） | `/judging` 评分页 |
| **参赛者** | 暂无（v2.2 不开放给参赛者直接用 AI 接口） | — |

## 2. Admin 完整操作手册

### 2.1 项目分析

**我能做什么？** 让 AI 评估一个或多个项目的质量（0-100 分 + 4 维度详情），不用我手动看每个项目。

**怎么用？**
1. 登录 admin → 进入 **AI 功能控制台** → 默认就在 "项目分析" tab
2. **单项目评估**：在项目详情页点 "AI 评估" 按钮（如果有），或调 API
3. **批量评估**：
   - 选一个当前 hackathon（"AI 功能控制台" 顶部）
   - 点 "开始批量分析"
   - **看到 taskId 提示** = 任务已启动
   - **进度条自动刷新**（每 2 秒一次），不用手动刷新页面
   - 完成后看到 "X / Y 完成（Z 失败）"
   - 点 "失败项目" 展开看具体哪些项目失败 + 错误原因

**重要开关**：
- **"强制重新分析" Switch**：默认关（用 24h 缓存）。如果你刚升级了 AI 模型 / 调整了 prompt，要重评所有项目，开它。

**常见问题**：
- Q: 任务启动后我关闭页面，任务会停吗？
  A: 不会。任务在服务器后台跑，下次回来看到进度条会继续更新。但 taskId 只保留 1 小时，1 小时后查不到。
- Q: 失败的项目要怎么处理？
  A: 看错误消息。常见原因：(a) AI provider 暂时不可用 → 等几分钟重试 (b) 项目描述为空 → 提示参赛者补充 (c) 项目过大被截断。

### 2.2 评分一致性分析

**我能做什么？** 看哪些评委打分偏严 / 偏宽，提醒他们调整。

**怎么用？**
1. 进入 "评分一致性" tab
2. 点 "分析评分一致性"
3. 看到每个评委的卡片：
   - **平均分**：该评委对所有项目的平均打分
   - **标准差**：该评委打分波动大小（越小越稳定）
   - **偏差**：相对全体均分的差（+10 以上偏宽，-10 以下偏严）
   - **AI 建议**：AI 给的"调整方向"建议
4. 找到偏差 > 10 的评委，私下沟通

**常见问题**：
- Q: "暂无评分数据" 是什么意思？
  A: 当前 hackathon 还没有任何评分记录。需要先分配评委 + 评委完成打分。
- Q: 标准差大说明什么？
  A: 该评委对不同项目打分差异大 — 不一定不好（如果好项目打高分、烂项目打低分，是好事），但要结合偏差一起看。

### 2.3 内容审核

**我能做什么？** 让 AI 帮我判断一段内容（项目描述、评论、用户资料）是否包含敏感词、垃圾信息、仇恨言论。

**怎么用？**
1. 进入 "内容审核" tab
2. 在文本框粘要审核的内容（最长 10K 字符，超过会自动截断）
3. **或者点 "样例" 按钮**：自动填入 spam / 正常 / 敏感 三种示例
4. 点 "审核内容"
5. 看到结果：
   - **是否合适**（绿勾/红叉）
   - **建议操作**：批准 / 人工审核 / 拒绝
   - **检测到的问题**：每个问题的类型（spam / 敏感 / 抄袭等）+ 严重度

**常见问题**：
- Q: AI 不可达时报什么错？
  A: 友好错误（"网络异常" / "服务异常" / "请求超时"），不会暴露内部信息。检查 `AI_API_KEY` 是否配对。
- Q: 10K 字符够用吗？
  A: 一般项目描述 1-2K 字，10K 足够。如果项目超长，建议先人工把关。

### 2.4 内容生成

**我能做什么？** 让 AI 帮我写 README、Pitch Deck 大纲、新闻稿、邮件、评分标准，或者优化现有项目描述。

**怎么用？**
1. 进入 "内容生成" tab
2. 选**类型**（6 选 1）：
   - 描述优化：粘原文，AI 改得更专业
   - README：项目名 + 描述 + 技术栈
   - Pitch Deck：项目名 + 描述 + 目标受众
   - 新闻稿：项目名 + 奖项 + 简介
   - 邮件：主题 + 收件人 + 场景
   - 评分标准：主题 + 赛事重点
3. 选**语言**（中文 / 英文）
4. 选**风格**（商务 / 学术 / 轻松 / 技术）
5. 在文本框粘输入（占位符会随类型变化提示该填什么）
   - **或者点 "填充示例"**：自动填入 README 示例
6. 点 "生成"
7. 看到结果，点 "复制结果" 一键复制

**48 种组合** = 6 类型 × 2 语言 × 4 风格，每个组合 AI 都会调出不同的 prompt 模板。

**常见问题**：
- Q: 输入太短会怎样？
  A: AI 生成的会很泛（"占位符建议"），尽量按占位符填全。
- Q: 风格选错可以重生成吗？
  A: 可以，调风格再点一次 "生成" 即可（不计费缓存）。

### 2.5 抄袭检测

**我能做什么？** 对比两段文本的相似度（0-100%），或检查单个项目跟同赛事其他项目的相似度。

**怎么用？**
1. 进入 "抄袭检测" tab
2. **粘两段文本**到 Text 1 / Text 2
3. **或者点 "填充示例"**：自动填入两个相似但措辞不同的项目描述
4. 点 "对比相似度"
5. 看到结果：
   - **相似度 %** + 进度条（绿/黄/红）
   - **风险等级**：高（>70%）/ 中（30-70%）/ 低（<30%）

**风险等级解读**：
- **> 70%**：高风险，建议人工核查 — 两个项目很可能互相抄袭或共享大量内容
- **30-70%**：中风险，可能是参考了同源资料 / 共享代码库 / 相同技术栈导致
- **< 30%**：低风险，正常的"看起来像"

**常见问题**：
- Q: 短文本为什么相似度总是 0%？
  A: AI 文本对比依赖语义分析，< 50 字符很难判断。可信度低。
- Q: 抄袭判定标准是什么？
  A: AI 主观判断 + 人工确认。仅作参考，最终判定要 admin 看证据。

### 2.6 AI 运行状态（Metrics）

**我能做什么？** 看 AI 服务健康度 — 调用次数、错误率、平均耗时、按 provider 分布。

**怎么用？**
1. 进入 "AI 运行状态" tab
2. 点 "刷新" 按钮（**不自动刷新** — 避免给 AI provider 加压）
3. 看到 4 个 metric card：
   - **总调用次数**：所有 AI 调用的总数
   - **总错误次数**：调用失败 + 超时的总数（橙色提示）
   - **超时次数**：超过 30s 的请求数（红色提示）
   - **平均耗时**：所有调用的平均 ms
4. 看到按 provider 分类的 calls / errors 列表

**什么时候要看**：
- 用户报 "AI 用不了" 时 → 看 errors > 0 / timeout > 0
- 看 provider 是不是挂了（如果只有 1 个 provider 报错，切到另一个）
- 评估 AI 成本（调用次数 × 每次成本）

**常见问题**：
- Q: 数据从哪里来？
  A: 服务器内存里的计数器（重启后清零）。要看历史需要接 Prometheus / 数据库记录。
- Q: "暂无数据" 是异常吗？
  A: 不是 — 新部署的项目正常 0 调用。

## 3. 评委（Judge）

评分页会自动调 `/api/ai/judge-suggestions/:assignmentId` 获取 AI 建议，但**前提是该项目之前有 admin 触发过 AI 评估**。

如果评分页没有 AI 建议卡片，说明：
- 该项目还没被 admin 评估过
- 或者 AI 评估在 24h 缓存外（虽然 v2.2 加了 24h 缓存但没自动刷新）

→ 跟 admin 反馈，admin 在 AI 功能控制台跑一下项目分析。

## 5. AI 没工作？排查清单

按顺序排查：

1. **检查 `.env` 配置**
   ```bash
   cat .env | grep AI_
   # 应该看到：
   # AI_PROVIDER=claude
   # AI_API_KEY=sk-ant-xxxxx
   ```

2. **检查 AI key 是否有效**
   - Claude: 登录 https://console.anthropic.com 看余额
   - OpenAI: 登录 https://platform.openai.com/usage

3. **检查 API 配额**
   - Claude Sonnet 4 默认 50 RPM（每分钟请求数），5 并发是安全的
   - 如果 429 太多，等几分钟后重试

4. **看 Metrics tab**
   - errors > 0 → 看具体 provider 报错
   - timeout > 0 → 可能是网络问题，AI 慢

5. **看后端日志**
   ```bash
   # 在跑 server 的 terminal 看 console.error 输出
   # 应该能看到 "AI call failed: ..." + safeErrorMessage 后的 category
   ```

6. **重启 server**
   - dev 环境：`getAIService` 是单例，AI 配错改 env 后必须重启
   - prod：用 `pm2 restart`

## 6. 常见问题 FAQ

**Q: AI 评估结果有主观性吗？**
A: 有。AI 给分是"参考"，最终判定仍要 admin / 评委。

**Q: AI 会不会替换评委？**
A: 不会。AI 是辅助 — 项目分析帮 admin 找"潜在好项目"，评分一致性帮 admin 找"评分异常评委"，但最终决定权在人。

**Q: AI 数据会上传到第三方吗？**
A: 是的。你贴的内容会发到 Claude / OpenAI 的 API。请确保内容**不包含**：
- 用户密码 / token
- 内部未公开的项目细节
- 受版权保护的内容（除非你有授权）

**Q: 数据库里历史 AI 评估能用吗？**
A: ⚠️ v2.1 的 AI 评估结果**不可信** — 那段时间 schema 模式 100% fallback，所有记录都是默认 50 分。v2.2 之后的评估是真 AI 评分。

**Q: 怎么彻底关掉 AI 功能？**
A: 不配置 `AI_API_KEY` 即可。所有 AI endpoint 会返回 "AI service misconfigured"，但项目其他功能不受影响。
